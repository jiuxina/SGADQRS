## SGADQRS (SCMS) 前端全面审查报告

审查范围：21个页面组件 + 布局系统 + 权限体系 + 跨页面共性问题
技术栈：React 19 + TypeScript + Vite 8 + Tailwind CSS v4 + Zustand + Motion

---

### 一、跨页面共性问题（影响全局）

| 严重度 | 问题 | 涉及页面 |
|--------|------|----------|
| **严重** | 硬编码 `localhost:8080`（4处）：`format.ts` resolveCoverUrl、`DesktopLayout.tsx` 头像URL、`ProfilePage.tsx` 头像显示、`config/env.ts` 回退值。部署到任何非本机环境全部失效 | 全局 |
| **严重** | 客户端搜索与服务端分页冲突：搜索只过滤当前页数据，但分页 total 仍显示未过滤的总数。用户搜索后看不到其他页的匹配记录，且分页控件误导 | AdminGrades, AdminRegistrations |
| **高** | 所有列表页缺少搜索防抖（debounce），每次按键触发一次API请求，大量无效网络请求 | Competitions, Users, Grades, Registrations 等全部含搜索的页面 |
| **高** | 所有表格页缺少列排序功能，无法按日期、名称、人数等排序 | 全部表格页面 |
| **高** | 管理员全部列表页缺少批量操作（批量审批/拒绝/删除/导出），只能逐条操作。注：教师竞赛管理的报名弹窗已有批量审核功能 | AdminCompetitions, AdminUsers, AdminRegistrations, AdminGrades, AdminNotices, TeacherTeams |
| **中** | 确认对话框不一致：部分页面用项目自有的 `confirmDialog()`，部分用浏览器原生 `confirm()`，视觉风格不统一 | AdminUsers vs AdminCompetitions/AdminNotices |
| **中** | 加载状态不完整：多数页面仅在首次加载显示骨架屏，切换筛选/翻页时无加载指示 | 全部列表页 |
| **中** | 空状态组件未统一使用：项目有 `EmptyState` 组件，但多数表格页用简单文字替代 | 大部分列表页 |
| **低** | catch 块的 console.error 消息是复制粘贴错误：Users页导出写"删除用户失败"，Grades页导出写"加载数据失败" | AdminUsers, AdminGrades |
| **低** | 无 ARIA 标签和键盘导航支持，图标按钮缺少无障碍描述 | 全部页面 |

### 二、管理员端（7个页面）

#### 2.1 AdminDashboard 仪表盘

| 维度 | 评价 |
|------|------|
| 功能合理性 | 展示了竞赛状态分布、待审核列表、用户/队伍统计、快速入口、近期提醒。基本覆盖了管理员首页需求 |
| 布局合理性 | Bento Grid 布局，视觉层次清晰。但统计卡片只占一行，下方大面积留给图表和列表，信息密度可优化 |
| 内容合理性 | 竞赛状态分布图只统计了第一页数据（非全量），"参赛队伍"卡片实际读取的是报名总数（字段名误导） |

问题清单：
1. 待审核列表不可点击，管理员无法直接跳转到审核页面
2. "系统设置"快速入口指向 `/admin/settings`，但该页面不存在（死链接）
3. 竞赛审核的 badge 数字硬编码为3，不随实际数据变化
4. 无手动刷新按钮，数据在页面停留期间会过时
5. 缺少近期操作日志/审计记录

#### 2.2 AdminCompetitions 竞赛审核管理

| 维度 | 评价 |
|------|------|
| 功能合理性 | 支持7种状态筛选、搜索、审核通过/拒绝（含拒绝原因）、查看详情、编辑、删除、导出。功能较完整 |
| 布局合理性 | 表格+筛选栏+分页，标准管理后台布局。详情弹窗信息完整 |
| 内容合理性 | 表格列：名称、发布者、报名时间、报名人数、状态。详情弹窗包含封面、描述、规则、附件等全量信息 |

问题清单：
1. 编辑按钮跳转到 `/teacher/competitions/:id/edit`（教师路由），架构上不合理，管理员不应走教师路由
2. 缺少批量审核（批量通过/拒绝），大量竞赛提交时效率极低
3. 详情弹窗内没有"通过"按钮，必须关闭弹窗后在表格行操作
4. 搜索无防抖
5. 缺少列排序
6. 已发布/进行中的竞赛即使报名人数为0也可删除，可能不合理
7. colSpan=7 但表格只有6列（HTML小错误）

#### 2.3 AdminUsers 用户管理

| 维度 | 评价 |
|------|------|
| 功能合理性 | 完整CRUD、角色筛选、启用/禁用、重置密码、头像上传、导出。功能覆盖全面 |
| 布局合理性 | 顶部统计卡片+筛选栏+表格+分页，布局合理。但统计卡片的学生/教师数只统计当前页，数据不准确 |
| 内容合理性 | 表格字段包含：用户名、姓名、角色、院系、性别、专业、班级、状态、最后登录。但缺少注册时间 |

问题清单：
1. 删除/禁用/重置密码全部使用浏览器原生 `confirm()`，与项目其他页面风格不一致
2. 顶部统计卡片的学生数/教师数仅基于当前页数据计算，非全量
3. `lastLoginTime` 字段通过类型断言强取，`UserItem` 类型中未定义该字段
4. 无批量操作（批量禁用、批量改角色）
5. 创建用户无密码强度校验
6. 性别标签使用语义色不当（男=绿色pass，女=橙色pending）
7. 导出的 catch 块错误日志写的是"删除用户失败"

#### 2.4 AdminStats 数据统计

| 维度 | 评价 |
|------|------|
| 功能合理性 | 展示8个KPI指标卡、6个月报名趋势图、竞赛热度排名、奖项分布图。但完全只读，无任何交互 |
| 布局合理性 | 指标卡+图表+排名的垂直布局。图表区用纯CSS手绘，非专业图表库 |
| 内容合理性 | 奖项分布的比例计算用 `count*10` 固定倍率（>=10即100%），比例失真。无趋势对比 |

问题清单：
1. 零交互：无日期范围筛选、无竞赛筛选、无下钻能力。本质是静态报表
2. 趋势图用CSS div拼接，折线实际是水平线段，非真正的折线图，渲染不可靠
3. 指标卡无同比/环比变化指示
4. 无导出功能（无法导出统计报表）
5. 竞赛排名无数量限制标识（无"Top 10"标签或"查看更多"）
6. 奖项分布无空状态处理（无奖项时该区域为空白）

#### 2.5 AdminNotices 通知公告管理

| 维度 | 评价 |
|------|------|
| 功能合理性 | 支持富文本编辑（TipTap）、发布/撤回、置顶/取消置顶、类型筛选。通知生命周期管理较完整 |
| 布局合理性 | 筛选栏+表格+分页。但缺少搜索框，大量通知时无法快速定位 |
| 内容合理性 | 表格列：置顶标识、标题、类型、状态、发布时间 |

问题清单：
1. 无搜索功能（所有其他管理页都有搜索，唯独通知公告没有）
2. 编辑时弹窗标题仍显示"发布新通知/公告"，未随操作变化
3. 弹窗中只有"发布"按钮，无法保存为草稿（编辑草稿时直接发布）
4. 发布前无内容校验，可发布空内容的通知
5. loading 状态被设置但从未读取，切换筛选时无加载指示
6. 置顶排序仅在当前页生效（跨页置顶不生效）
7. 富文本编辑器工具栏过于简陋（无标题层级、无图片、无对齐、无撤销重做按钮）

#### 2.6 AdminGrades 成绩管理

| 维度 | 评价 |
|------|------|
| 功能合理性 | 按竞赛筛选、搜索、查看成绩、发布成绩、导出。但成绩只读不可编辑，管理员无法修正数据 |
| 布局合理性 | 竞赛选择器+搜索+表格+分页。标准布局 |
| 内容合理性 | 表格列：竞赛名、学生(队伍)、分数、排名、奖项、发布状态 |

问题清单：
1. 发布按钮在每行，但实际是发布该竞赛全部成绩（UI暗示单条操作，实际是批量操作，极易误导）
2. 管理员无法编辑/修正任何成绩（只读），数据纠错完全依赖教师端
3. 搜索只过滤当前页+分页total不准（共性问题）
4. 无已发布/未发布状态筛选
5. 缺少学号等标识字段，同名学生无法区分
6. 存在重复的数据获取逻辑（loadData 和 useEffect 中有相同的搜索过滤代码）

#### 2.7 AdminRegistrations 报名审核

| 维度 | 评价 |
|------|------|
| 功能合理性 | 竞赛筛选、状态筛选、搜索、审核通过/拒绝、导出。基本流程完整 |
| 布局合理性 | 竞赛选择器+状态筛选+搜索+表格+分页。标准布局 |
| 内容合理性 | 表格列：竞赛名、学生(队长标识)、队伍名、联系电话、报名时间、状态、审核操作 |

问题清单：
1. 拒绝操作无原因输入（后端支持 auditRemark，但UI未暴露）。对比竞赛审核有拒绝原因弹窗，不一致
2. 无详情展开/弹窗：看不到报名备注、附件、队伍成员详情
3. 搜索+分页冲突（共性问题）
4. 无批量审核
5. 审核操作无确认对话框，点击即执行，误操作无法挽回
6. 联系电话不可点击（移动端无法直接拨打）
7. 缺少学生的院系/专业/班级信息，不便于资格审核

### 三、教师端（5个页面）

#### 3.1 TeacherDashboard 仪表盘

| 维度 | 评价 |
|------|------|
| 功能合理性 | 展示我的竞赛数、最近竞赛列表、快速入口（竞赛管理/团队管理/成绩录入/消息通知）、近期提醒 |
| 布局合理性 | 统计卡片+快速入口+竞赛列表+提醒，结构清晰但信息量偏少 |
| 内容合理性 | 竞赛统计有两个数字（"我发布的竞赛"总数 vs 列表显示的竞赛数），含义模糊 |

问题清单：
1. 竞赛列表项不可点击，无法跳转到竞赛详情或管理页
2. "消息通知"快速入口指向 `/teacher/messages`，该路由不存在（死链接）
3. 竞赛列表为空时无空状态提示
4. 缺少待审核报名数、被拒绝竞赛数等需要教师关注的信息
5. `stats` 字段用 `Record<string, unknown>` 无类型安全，所有字段访问需要手动断言
6. 竞赛数统计只显示当前页数量，非全量

#### 3.2 TeacherCompetitions 竞赛管理

| 维度 | 评价 |
|------|------|
| 功能合理性 | 状态筛选、分页、管理报名（弹窗含批量审核）、编辑、提交审核、删除。核心流程覆盖 |
| 布局合理性 | 表格+状态筛选+分页。操作列最多4个按钮，略拥挤 |
| 内容合理性 | 表格列：封面、名称、报名时间、报名人数、状态、操作 |

问题清单：
1. 报名管理弹窗无分页和搜索，报名超过 `PAGE_SIZE.LARGE` 条时数据被截断
2. 主表格无搜索功能
3. 批量拒绝用同一个备注给所有学生，无法逐一写原因
4. 无报名列表导出功能
5. colSpan=7 但表格只有6列
6. 操作列按钮密度高，"管理/编辑/提交审核/删除"在小屏幕可能溢出

#### 3.3 TeacherCompetitionCreate 竞赛创建/编辑

| 维度 | 评价 |
|------|------|
| 功能合理性 | 表单字段：名称、封面、主办单位、描述、规则、奖项(动态列表)、报名/比赛时间、地点、最大人数/队伍、附件上传。支持保存草稿和提交审核 |
| 布局合理性 | 单列表单布局，字段分组清晰。封面上传有预览和拖拽 |
| 内容合理性 | 缺少竞赛分类、参赛资格、联系人信息、是否允许个人参赛等字段 |

问题清单：
1. 描述和规则用纯文本 textarea，无富文本编辑器（AdminNotices 有 TipTap，教师端反而没有）
2. 无离开确认（beforeunload），误关闭页面丢失所有表单数据
3. `competitionEnd` 拼接 `'00:00:00'`（当天凌晨），实际效果是比赛提前一天结束，应为 `'23:59:59'`
4. 无预览功能，教师无法看到学生端的展示效果
5. 草稿保存无表单校验，日期为空时生成畸形时间字符串
6. 草稿保存按钮无防重复点击（无 submitting 状态锁）
7. 缺少关键字段：竞赛分类/类型、参赛资格（年级/院系/绩点）、联系人、是否允许个人参赛
8. 奖项层级删除后重新添加会出现编号跳跃（如删掉2再加变成3）

#### 3.4 TeacherTeams 团队管理

| 维度 | 评价 |
|------|------|
| 功能合理性 | 竞赛筛选下拉框、团队列表（可展开成员详情）、审核通过/拒绝 |
| 布局合理性 | 表格+展开行。可展开的成员信息包含姓名、学号、专业、状态、加入时间 |
| 内容合理性 | 表格列：团队名、口号、竞赛、队长、成员数、状态、操作 |

问题清单：
1. 无搜索功能（无法按团队名/队长名搜索）
2. 无状态筛选（无法只看"已提交"待审核的团队）
3. 无批量审核
4. 审核拒绝时不能填写原因
5. 竞赛下拉框未过滤 `publisherId`，显示系统所有竞赛（应该只显示该教师发布的）
6. 审核按钮在"组建中"状态也显示，可能导致团队尚未组建完就被审核
7. "学号"列实际显示的是 `studentUsername`（可能是邮箱或登录名，不一定是学号）
8. 团队数量显示当前页数量，非全量

#### 3.5 TeacherGrades 成绩录入

| 维度 | 评价 |
|------|------|
| 功能合理性 | 竞赛选择器、成绩列表、单个成绩编辑弹窗、发布成绩、分数分布SVG直方图 |
| 布局合理性 | 统计卡+分布图+表格。结构合理但统计只基于当前页 |
| 内容合理性 | 表格列：学生/团队、分数、排名、奖项、备注、状态、操作。统计：平均分/最高分/最低分 |

问题清单：
1. 无批量录入功能（只能逐个编辑，这是成绩管理最核心的缺失）
2. 无 CSV/Excel 导入功能
3. 无导出功能
4. 统计数据（平均/最高/最低分）只计算当前页数据，非竞赛全量数据（严重数据准确性问题）
5. 分数分布直方图用8个固定分箱，所有分数相同时标签重复显示
6. 发布按钮始终可见，即使无成绩可发布
7. 发布时不校验成绩是否已填写，null 分数的记录也会被发布
8. 缺少中位数、标准差、及格率等常用统计指标
9. 无分数范围校验的UI提示（如0-100）

### 四、学生端（7个页面）+ 公共页面

#### 4.1 LoginPage 登录页

| 维度 | 评价 |
|------|------|
| 功能合理性 | 用户名+密码+角色切换+登录+注册入口。基本功能完整 |
| 布局合理性 | 居中卡片式登录框，角色切换用 Tab/Segmented 控件 |
