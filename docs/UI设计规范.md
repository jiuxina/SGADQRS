## 界面设计规范

### 色彩与状态层级

界面中的色彩使用遵循"越少越好"的原则。强调色（accent）仅用于页面中最核心的可交互元素，如当前唯一的 CTA 按钮、进度指示、关键数值高亮。其余所有元素统一使用三级灰度体系：主文本色、次要文本色、弱化文本色。

状态元素的视觉权重应与其可操作性成正比。可操作的状态（如"报名中"、"审核中"）使用对应的语义色徽章；已终态的、不可操作的状态（如"已截止"、"已过期"、"已禁用"）应降低视觉权重，仅使用弱化文本色呈现，不使用彩色背景或边框。错误和警告同理——提示文字使用弱化色即可，不需要红色背景块来"大声宣告"。

### 按钮

同一操作区域内的按钮保持风格一致。当多个按钮并列出现时（如卡片底部的"查看详情"与"立即报名"），统一使用次级按钮（ghost / outline 风格），避免主次混用。仅当某个按钮是该视图下唯一的核心行动入口时，才使用主色填充按钮（primary）。

禁用状态的按钮应降低透明度或切换为弱化色文字，而非改变按钮类别。

### 图标

图标直接以裸图标形式呈现，不使用带色背景的容器包裹。图标颜色统一使用弱化文本色，与周围文字保持视觉一致性。图标尺寸与相邻文本字号匹配（通常 14–16px），不刻意放大。

仅在图标本身承载语义区分功能时（如用不同颜色区分"通过"与"拒绝"），才为图标赋予语义色。

### 卡片与布局

卡片只承载用户决策必需的信息。如果某项信息在页面的其他位置（如筛选器、详情页）已经存在，卡片上不再重复展示。每张卡片上的标签/徽章数量控制在一个，不堆叠。

指标卡片区域采用紧凑布局：减小内边距、收窄网格间距、降低数值字号，避免指标行占据过多垂直空间。指标行与下方内容区域的间距应明显小于页面级间距，形成紧密的视觉分组。

### 列表

列表项不使用装饰性圆点或色块作为视觉引导，直接以文本排列呈现。附属数据（如人数、日期）使用弱化色右对齐显示，不添加额外样式修饰。

### 弹窗与模态框

弹窗继承与页面卡片相同的基础样式（如毛玻璃、圆角、边框），但禁用装饰性高光效果（如顶部渐变反射、光泽动画），避免在半透明遮罩背景下产生不自然的视觉伪影。

弹窗内的信息密度应与页面保持一致，不因"这是弹窗"而使用更大的字号或更多的留白。

### 成功与失败反馈

成功和失败的反馈遵循对称的设计语言。成功使用庆祝类动效（如彩带）表达正向情绪；失败使用克制的提示卡片 + 矢量图标 + 进度条，不使用大面积红色覆盖、emoji 表情、碎片散落动画等过度情绪化的元素。

反馈弹窗应具备自动关闭机制（通过定时器控制），并在底部显示倒计时进度条，让用户对关闭时间有明确预期。

### 状态徽章

表格和列表中的状态展示统一使用语义化徽章组件（如 pass / reviewing / pending / fail），不额外搭配状态圆点或其他冗余指示器。一个语义清晰的徽章足以传达状态。

### 总体原则

少即是多，安静即专业。去掉一切不承载信息的装饰元素，让用户的注意力聚焦在真正重要的数据和操作上。
