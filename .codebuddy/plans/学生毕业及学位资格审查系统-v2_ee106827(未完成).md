## 产品概述

"学生毕业及学位资格审查系统"是一个面向高校的**辅助决策型业务系统**，用于帮助教务处、院系负责人、教师快速发现学生毕业及学位资格审核中的问题，减少人工计算错误，提高审核效率。系统定位为**辅助工具而非全自动审核**，最终审核决策仍由人工完成。

## 核心功能

- **多角色权限管理**：学生（查看个人预警与审核结果）、辅导员/教师（查看班级预警学生）、院系负责人（本院系审核辅助）、教务处管理员（全校审核看板、规则配置）
- **数据导入管理**：优先支持Excel导入学生、课程、成绩数据；有条件时对接教务系统中间库
- **培养方案管理**：各专业毕业要求配置（总学分、必修课、选修课、实践环节、学位绩点等）
- **学生预警功能**：提前一学期预警可能无法毕业的学生，告知缺哪些条件
- **审核辅助看板**：教务处快速筛选问题学生，查看未通过原因明细
- **学籍异动处理**：休学、复学、转专业、降级、延长学制的审核适配
- **成绩性质管理**：补考、重修、免修、免考、学分认定的标记与处理
- **课程替代管理**：课程替代关系配置、学分认定申请记录
- **报表与导出**：审核统计报表、毕业/学位名单导出、正式Word文档生成
- **系统管理**：用户管理、操作日志、数据备份

## 非核心功能（延后）

## 系统定位修正

**从"全自动审核系统"改为"毕业资格审核辅助决策系统"**：

- 核心目标是**预警、统计、报表、减少人工计算错误**
- 不追求"全自动"，追求"人工审核时有数据支撑"
- 审核结果需人工确认，系统提供数据依据和明细

## 技术栈选择

| 层级 | 技术选型 | 选型理由 |
| --- | --- | --- |
| **前端框架** | React 18 + TypeScript + Vite | 组件化开发，Vite构建快，适合Agent快速迭代 |
| **UI组件** | Tailwind CSS + shadcn/ui | 原子化CSS，组件可复用，现代化设计 |
| **后端框架** | Express.js + TypeScript | 轻量简单，学习成本低，高校IT人员易维护 |
| **数据库** | MySQL 8.0 | 高校普遍使用，运维人员熟悉，与现有系统一致 |
| **ORM** | Prisma | 类型安全，迁移方便，开发效率高 |
| **文档生成** | docx.js | 客户端Word生成，减轻服务端压力 |
| **Excel处理** | xlsx.js | 前端导入导出Excel，无需服务端处理 |
| **部署** | PM2 + Nginx | 传统部署方案，学校IT部门熟悉 |


## 架构策略

采用**简单分层架构**：

```
客户端 (React + Vite)
    │
    ▼
Nginx (反向代理 + 静态资源)
    │
    ▼
Express API (业务逻辑 + 数据校验)
    │
    ▼
Prisma ORM (数据库访问)
    │
    ▼
MySQL 8.0 (数据存储)
```

### 关键技术决策

1. **单仓库结构**：前后端在一个Git仓库，根目录分`frontend/`和`backend/`，降低复杂度
2. **Express替代NestJS**：减少装饰器、依赖注入等概念，代码更直观，维护门槛低
3. **MySQL替代PostgreSQL**：与高校现有技术栈保持一致，DBA会维护
4. **无Redis/BullMQ**：初期用MySQL任务表实现异步，真有性能问题再引入
5. **Excel导入优先**：提供标准Excel模板，支持批量导入学生、课程、成绩数据
6. **规则配置用JSON文件**：初期规则变更通过修改配置文件+发版实现，不做可视化编辑器

### 性能与可靠性

- 单学生审核：直接SQL查询计算，响应时间<3秒
- 批量审核：数据库轮询任务表，支持100人/批次
- 并发：Express单进程可支持200+并发，足够高校场景
- 数据安全：密码bcrypt加密、JWT认证、SQL参数化防注入

## 关键代码结构

```typescript
// 审核规则配置（JSON配置文件）
interface AuditRule {
  id: string;
  name: string;
  degreeType: 'bachelor' | 'master' | 'doctor';
  majorId?: string;           // 空表示通用规则
  totalCredits: number;       // 总学分要求
  requiredCourses: string[];  // 必修课课程代码列表
  electiveCredits: number;    // 选修课学分要求
  practiceRequired: boolean;  // 是否需要实践环节
  thesisRequired: boolean;    // 是否需要毕业论文
  minGPA: number;             // 最低平均绩点
  minDegreeGPA: number;       // 最低学位课程绩点
}

// 学生审核结果
interface StudentAuditResult {
  studentId: string;
  studentNo: string;
  name: string;
  major: string;
  graduationStatus: 'passed' | 'failed' | 'warning';
  degreeStatus: 'passed' | 'failed' | 'warning';
  missingItems: MissingItem[];  // 缺少的条件明细
  totalCredits: number;
  gpa: number;
  calculatedAt: Date;
}

// 缺少的条件
interface MissingItem {
  type: 'credit' | 'course' | 'gpa' | 'practice' | 'thesis';
  name: string;           // 条件名称
  required: string;       // 要求
  actual: string;         // 实际
  suggestion?: string;    // 建议（如"建议选修XX课程"）
}
```

## 设计风格

采用**现代政务/教育管理系统风格**——专业、清晰、高效。以浅色调为主，搭配沉稳的蓝色系，营造权威可信赖的视觉感受。界面布局遵循"信息密度高但层次分明"的原则，适合大量表格、表单的审核业务场景。

### 页面规划（核心页面）

1. **登录页**：简洁大气，学校Logo + 登录表单
2. **学生端-审核结果页**：个人毕业/学位审核结果总览，清晰展示通过/未通过项，重点突出"还差什么"
3. **教师端-班级预警页**：班级学生列表，预警学生红色标记，快速查看缺什么条件
4. **教务处-审核看板**：全校学生审核状态统计，问题学生筛选，支持按院系/专业/班级筛选
5. **教务处-培养方案管理**：各专业毕业要求配置表单
6. **教务处-数据导入页**：Excel上传、数据预览、导入确认

### 设计细节

- **布局**：侧边导航 + 顶部面包屑 + 内容区，内容区采用卡片式布局
- **表格**：审核结果表格使用行内状态标签（通过/未通过/预警），支持展开查看详情
- **数据可视化**：审核进度使用环形图，各院系通过率使用柱状图
- **交互**：批量操作提供确认弹窗；长时间操作显示进度条；表格支持排序筛选
